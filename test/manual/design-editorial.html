_hyperstream

A protocol for streaming HTML to subscribed DOM nodes. Hypermedia, all the way down. Five kilobytes brotli, zero dependencies.

trace mark · v0.1
By the Big Sky Foundry 10 min read Filed: real-time, hypermedia, htmx

Server-push hypermedia has lived as an afterthought for too long. htmx ships brilliant primitives for request and response, and _hyperscript handles client-side behaviour with the same locality-of-behaviour grace. What remains uncovered is the third leg: the moment a server has something new to tell every browser that cares.

Today that gap is filled with bolted-on JSON envelopes, OOB swap workarounds, and ad-hoc reconnect logic. _hyperstream closes it.

“The server speaks HTML. The browser swaps HTML. There is nothing in between.”

The wire is a fragment.

Every push is a self-describing custom element. No parsing, no envelope, no translation step. 

// the entire wire format
<hs-fragment channel="auction:lot-1"
              seq="42"
              target="#price"
              swap="inner">
  <strong>$120</strong>
</hs-fragment>

That single shape, applied recursively, expresses subscriptions, atomic batches, partial streams, replay handshakes. Read it in any inspector. Paste it into any test. Diff it in any review.

Subscribe in HTML.

The client says nothing about state. It says which channel each node listens to, then yields control. Reconnects, cursor replay, multi-element fan-out, atomic swaps, suspense for partials, all of it lives behind a handful of attributes.
