The Server Speaks HTML. Now What?

A new protocol joins the htmx family. Subscribe in HTML, replay on reconnect, fan out one push to many DOM nodes. No JSON envelope. No client signals. Just hypermedia, all the way down.

Server-push hypermedia has lived as an afterthought for nearly a decade. htmx ships brilliant primitives for request and response. _hyperscript handles client-side behaviour with the same locality grace. What remained uncovered was the third leg: the moment a server has something new to tell every browser that cares.

Today that gap is filled with bolted-on JSON envelopes, OOB-swap workarounds, and ad hoc reconnect logic. _hyperstream closes it.

FIG. 1 — TRACE MARK, V0.1

"The wire is HTML.
The browser swaps HTML.
There is nothing in between."

Every push is a single, self-describing custom element. The same shape covers fragment swaps, atomic batches, partial streams, subscribe acks. Read it in any inspector. Paste it into any test. Diff it in any review.

// the entire wire format, in one envelope
<hs-fragment channel="auction:lot-1"
              seq="42"
              target="#price"
              swap="inner">
  <strong>$120</strong>
</hs-fragment>

That single shape, applied recursively, expresses subscriptions, atomic batches, partial streams, replay handshakes. Read it. Paste it. Diff it.

Subscriptions live on the page itself. The client says nothing about state. It says which channel each node listens to, then yields control. Reconnects, cursor replay, multi-element fan-out, atomic swaps, suspense for partials, all of it lives behind a handful of attributes.
