docs

_hyperherald pushes HTML fragments over SSE or WebSocket. Subscribe an element to a channel, the server publishes fragments, the browser swaps them in. 5KB brotli, zero deps.

install

Pick one.

<!-- CDN, dev only -->
<script src="https://cdn.jsdelivr.net/npm/hyperherald.org@0.0.1"></script>

# npm
npm install hyperherald.org

// ESM
import 'hyperherald.org';

your first subscription

Subscribe an element to a channel. The server publishes fragments addressed at children IDs.

<div _herald="/sse"
     _herald-subscribe="orders:42">
  <span id="status">pending</span>
  <span id="total">$0</span>
</div>

Server sends:

<hh-fragment channel="orders:42"
             target="#status"
             swap="inner">
  shipped
</hh-fragment>

attributes reference

attributeexamplepurpose
_herald/sseopen connection at URL. Multiple elements same URL share one socket.
_herald-subscribechat:42 lobbyspace-separated channels. Sent via query (SSE) or handshake frame (WS).
_herald-coalescekey:#price window:200ms strategy:lastdrop intermediate frames within window per key.
_herald-buffermax:50 drop:oldestbackpressure, bounded queue.
_herald-suspensetokens-1slot for hh-partial chunks (LLM streaming).
_herald-transportsse | ws | autoforce a transport. Default auto = SSE.
_herald-debugtrueverbose console logs.

frame types

Five wire types. Details on the spec page.

  • hh-fragment: single swap.
  • hh-multi: array of fragments, applied in order.
  • hh-atomic: buffered, applied in one mutation.
  • hh-partial: append progressive chunks (LLM tokens).
  • hh-subscribe-ack: server confirms subscribe plus replay cursor.
