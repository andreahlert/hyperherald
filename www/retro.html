hyperherald

Finally... server-push hypermedia for the web

HTML on the wire, announced to the DOM: declarative subscribe, replay, atomic and multi swaps over SSE or WS.

5KB brotli, zero dependencies, install with a script tag.

auction.html
<!-- subscribe a fragment to a channel -->
<div _herald="/sse"
     _herald-subscribe="auction:lot-1">
  <span id="price">$100</span>
  <span id="leader">nobody</span>
  <span id="countdown">60</span>
</div>

<!-- server pushes pure HTML envelopes -->
<hh-atomic channel="auction:lot-1" seq="42">
  <hh-fragment target="#price" swap="inner">
    <strong>$120</strong>
  </hh-fragment>
</hh-atomic>

HTML Over The Wire

Frames are self-describing custom elements: <hh-fragment>, <hh-multi>, <hh-atomic>, <hh-partial>. No JSON envelope. Hypermedia from server to DOM, no translation layer.

Pub/Sub Native

Multiple elements subscribe to one channel. One frame fans out to N targets. Multi-tab atomic updates without OOB hacks.

Replay On Reconnect

Per-channel cursor in sessionStorage, resumed via Last-Event-ID on SSE or handshake frame on WS. No gaps.

Composes With htmx

Pushed HTML can carry hx-* attrs. htmx upgrades them via MutationObserver. Same cascade as _hyperscript.

Atomic Swaps

Buffer multiple fragments, flush in one DOM mutation. Price plus leader plus countdown swap together. No flicker, no partial states.

Backpressure Built In

Coalesce by key, throttle by window, bound the queue. _herald-coalesce and _herald-buffer declarative on the element.

_hyperherald is v0, working towards 1.0. The wire format may change. Track the spec and the repo for breaking changes.
