the herald

Hear ye, hear ye

_hyperherald takes its name from a medieval office: the messenger who carried sealed decrees from the king to the town square and read them aloud, exactly as written, in order.

The role

A medieval herald received sealed envelopes from a trusted source, carried them across distance, and announced their contents to anyone within earshot. If the seal was unbroken and the parchment intact, the announcement stood.

That is the protocol in one sentence. The server is the king. The envelopes are signed HTML fragments. The library is the herald.

The herald's contract

The role is narrow on purpose. A herald carries the message. The DOM is the current rendering, the server is the record.

  • State lives with the king. The DOM is a projection of server state, not a parallel ledger.
  • Order is preserved. seq on every envelope, cursor on reconnect.
  • HTML in, HTML applied. The wire is the markup the browser already knows how to parse.
  • One connection per origin. Many channels ride together. The browser's connection budget is spent once.

The unbroken seal

The seal lives on the king's side. Authentication, authorization, payload validation belong with the publisher. The wire is HTML, and HTML from a hostile publisher is an XSS vector. The library is honest about where trust sits.

Multi-tenant kingdoms sanitize before sealing.
