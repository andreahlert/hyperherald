live auction

Open this page in two or three tabs. Place a bid in any tab. The other tabs update price, leader and countdown via _hyperherald push. No JSON, no client state.

server push _herald (_hyperherald) + user action hx-post (htmx4 alpha8)

how to test

  1. Start the auction server. In a terminal, from hyperherald/: 
    node test/manual/auction-server.js
# > hyperherald auction listening on http://localhost:3000/auction.html
  2. Open this page in two or three tabs. http://localhost:3000/auction.html times 3. Each tab subscribes to auction:lot-1 via SSE.
  3. Place a bid in tab 1. Type a name and an amount higher than the current price. Submit. htmx posts to /bid, server validates, then publishes an hh-atomic frame to all subscribers.
  4. Watch tabs 2 and 3 update at the same time. Price, leader, countdown all swap in one mutation. No flicker, no partial states.
  5. Test reconnect plus replay. Close one tab, place 2 more bids in another tab, reopen the closed one. It catches up via Last-Event-ID cursor. No gaps.

if nothing updates

  • Confirm the auction-server is running on :3000. Open /auction.html via that port, not via file://.
  • Check the browser console. _herald-debug is on, you should see [_hyperherald] subscribed and frame logs.
  • If the bid form 404s, the server didn't mount /bid. Restart the server.

what this proves

  • Subscribe per item. Tabs share one channel, server publishes once.
  • Atomic swap. Price, leader, countdown swap as a single mutation.
  • htmx coexists. Bid form uses hx-post; the response triggers an _hyperherald broadcast.
  • Replay on reconnect. sessionStorage cursor, server catches you up.
